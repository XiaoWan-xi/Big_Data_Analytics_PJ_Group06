# Agent 运行行为画像与异常发现

大数据分析技术期末项目 · 第 6 组 · 选题 5

我们分析 GitHub Agent 工作流的真实运行记录，回答三个问题：一个工作流通常怎样运行？一次执行或一段活跃期何时偏离历史规律？加入执行日志后，哪些原本看似正常的运行值得复核？最终在课程集群完成批处理，通过交互演示把每项结论追溯到工作流、运行和日志证据。

## 开发者第一次运行

克隆仓库后，从课程发布材料取得原始课件和教师发放的 GH-AWTrace 资料，按上表文件名放回对应位置。原始归档、论文、读取脚本和课程项目 PPT 均作为本地参考材料使用。

从本目录执行，适用于带 Python 3 和 `unar` 的 macOS/Linux 环境。先在自己的 Python 虚拟环境中准备 `pyarrow` 和 `pandas`（可用 `python3 -m pip install pyarrow pandas`）。以下操作只把两个分片解到新建的临时目录，适合确认脚本和字段。

```sh
export PJ_SAMPLE_DIR="$(mktemp -d)"
unar -q -D -o "$PJ_SAMPLE_DIR" GHAWTrace_ref/runs.rar \
  runs/part-00000.parquet runs/part-00001.parquet
python3 - <<'PY'
import os
import sys
from pathlib import Path

sys.path.insert(0, str(Path("GHAWTrace_ref").resolve()))
import read_runs

read_runs.RUNS_DIR = str(Path(os.environ["PJ_SAMPLE_DIR"]) / "runs")
columns = ["run_id", "event", "conclusion", "created_at", "run_attempts"]
shard_sizes = [len(frame) for frame in read_runs.iter_shards(columns)]
assert shard_sizes == [25_000, 25_000], shard_sizes
print(f"{len(shard_sizes)} 个分片，共 {sum(shard_sizes):,} 行")
PY
```

成功会输出 `2 个分片，共 50,000 行`。全表核数时将 165 个分片解至单独数据目录，将同一个 `RUNS_DIR` 设为**实际包含 Parquet 文件的目录**，安装 `duckdb` 后可用 `read_runs.query("SELECT count(*) AS n FROM runs")`，期望为 4,112,526。工作流画像直接读取运行表；日志任务以每个 TAR 为单位处理，按 `run_id + attempt` 定位归档，再以 `run_id` 连接。

## 系统设计与开发顺序

| 层次 | 输入 → 输出 | 本层回答的问题 |
|---|---|---|
| 集群数据层 | Parquet 分片 → 清洗 run 表 → 工作流画像、工作流周序列 | 数据有多大？各指标分母、观察时段和集群作业能否复核？ |
| 基础分析 | 画像 → 聚类原型；历史窗口＋当前 run/周 → 行为与生命周期异常 | 工作流属于哪类？是本次耗时偏高，还是长期节律发生了变化？ |
| 进阶分析 | 仓库 TAR → attempt 指纹 → run 指纹 → 同批 run 的结构化/联合排名 | 哪些异常在加入日志后更明显？能定位到哪次尝试的哪行？ |
| 系统演示 | 已产出的分析表 → 原型分布 → 工作流时间线 → 运行及日志证据 | 其他人能否复查一项具体发现？ |
